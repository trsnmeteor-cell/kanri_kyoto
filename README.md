# 京都・滋賀エリア 運用モニター

スプレッドシートの「超過」「ご意見」シートを **ブラウザから直接取得して表示**する、単一 HTML アプリです。
ビルド不要・サーバ不要。データは開くたび／「最新を取得」を押すたびにスプレッドシートから読み込まれます。

## データの流れ

```
Google スプレッドシート
      │  gviz JSONP（ブラウザから直接取得・サーバ不要）
      ▼
 index.html  ──失敗時──▶  同梱スナップショット（data/data.json）
```

- 取得は **Google の gviz エンドポイントを JSONP で呼ぶ**方式です（CORS の影響を受けずに動きます）。
- 対象は **店舗 / 超過 / ご意見 の3シート**。**超過の一覧も毎回シートから取得**し、
  「超過一覧」の見出し横に「超過シートから取得 … ・ n名」と表示します。
- 取得に失敗した場合（オフライン・共有設定の変更など）は、同梱の `data/data.json`
  （最終スナップショット）で表示し、右上に「オフライン表示」と表示します。**データが空にはなりません。**
- 右上のステータスに「シート取得済 日時（n か月）」と出れば、取得できています。
- **「最新を取得」ボタン** … その場で再取得します。タブに戻ってきたとき（10分以上経過時）も自動で再取得します。

### 月の自動認識

「ご意見」シート内の **「集計期間」ブロックを自動検出**して、月の一覧を作ります。
シートに新しい月の集計ブロックを追加すれば、**選択肢・前月比較・分析が自動で増えます**（アプリの修正は不要）。

## 収録画面

| タブ | 内容 |
| --- | --- |
| 01 超過（時間外労働） | 超過時間・超過回数・今後の労働時間。氏名/店舗で検索、列クリックで並べ替え |
| 02 ご意見（月別） | 月を選択 → その月の店舗×カテゴリ集計 ＋ 前月との増減 |
| 03 分析レポート | 対象月と比較月を選択 → カテゴリ構成・店舗別の増減・読みどころを自動計算 |
| 04 店舗チェック | **店舗番号を入力**（シートの入力セル G5 と同じ考え方）→ その店舗の指摘項目と指摘回数、カテゴリ別の傾向、全店比較を表示 |

### PDF出力（タブごとに出力内容を固定）

画面右上の **「PDF出力」** ボタン → ブラウザの印刷画面で「PDFに保存」。
**画面全体をそのまま印刷するのではなく、タブごとに決まった雛形（A4縦）が出力されます。**

| 開いているタブ | PDFに出力される内容 |
| --- | --- |
| 01 超過（時間外労働） | **超過一覧**（店舗№ / 店舗名 / 従業員番号 / 氏名 / 超過時間 / 超過回数 / 今後の労働時間 ＋ 合計行） |
| 02 ご意見（月別） | **前月との比較**（カテゴリ別 件数 ＋ 店舗別 件数、いずれも増減・合計つき） |
| 03 分析レポート | **店舗別 件数と増減**（対象月・比較月・増減・合計） |
| 04 店舗チェック | **店舗チェック 指摘状況**（店舗情報・カテゴリ別 指摘回数 ＋ 指摘項目一覧） |

- 出力にはヘッダー（タイトル・対象期間・出力日時・データ取得元）と注記が入ります。
- サイドバー・ボタン・KPIカード・グラフバーは PDF には入りません（数値のみ）。
- 超過一覧は **画面での絞り込み・並べ替えを反映**した状態で出力されます。
- A4縦・1ページに収まるよう行間と文字サイズを調整しています。
  特に **ご意見（月別）** は「カテゴリ別 件数」と「店舗別 件数」の2表を
  **必ず1ページに収める**ため、このシートのみ行間を詰めています（`.s-feedback` の圧縮ルール）。

#### 超過一覧は人数が増えても1ページ（自動フィット）

超過一覧は対象者が増えても **必ず1ページ**に収まるよう、出力時に自動調整します。

1. **自動縮小**：行数に応じて文字サイズ・行間を縮小し、A4縦の印刷可能領域（約958px）に収まる
   最大サイズを二分探索で決定します（`fitSheet()`／CSS変数 `--fit-chouka`）。
2. **2段組への自動切替**：対象者が **34名を超える**と、自動的に左右2段組で掲載し
   収容力を約2倍にします（このとき従業員番号は省略）。合計・小計は各段と下部に表示します。

実測での収まり（A4縦の内容幅658px・印刷可能高さ958pxで検証）:

| 対象者数 | レイアウト | 適用スケール | 内容高さ |
| ---: | --- | ---: | ---: |
| 27名 | 1段 | 1.00 | 906px |
| 63名 | 2段 | 0.59 | 929px |
| 120名 | 2段 | 0.52 | 957px |

分析レポート（店舗別 件数と増減）にも同じ自動フィットを適用しています。

#### 実装メモ（レイアウトを編集したいとき）

`index.html` 内の `#print-root` にある3つの `.sheet`（`#print-chouka` / `#print-feedback` / `#print-analysis`）が
PDFの雛形です。中身は `renderPrintChouka()` / `renderPrintFeedback()` / `renderPrintAnalysis()` が生成します。
スタイルは `#print-root ...` の規則（`@media print` の外）にまとまっているため、画面確認とPDF出力で同じ見た目になります。
用紙と余白は `@media print{ @page{size:A4 portrait; margin:20mm 18mm} }` で指定しています（上下20mm・左右18mm）。
余白を変えたい場合はこの数値を調整してください。

## ファイル構成

```
.
├── index.html                  # アプリ本体（単体で動作・データ取得ロジック込み）
├── data/data.json              # 取得失敗時に使う同梱スナップショット
├── scripts/extract.py          # スナップショットを更新する抽出スクリプト（任意）
├── .github/workflows/pages.yml # GitHub Pages 自動デプロイ
├── .nojekyll                   # Jekyll 処理を無効化
├── push.sh                     # 初回 push 補助
└── .gitignore
```

## ローカルで開く

`index.html` をブラウザで開くだけです（インターネット接続があればシートから最新を取得）。
サーバ経由なら:

```bash
python3 -m http.server 8000   # → http://localhost:8000/
```

## 複数端末で使う（公開）

1. GitHub でリポジトリを作成して push

   ```bash
   git remote add origin https://github.com/<ユーザー名>/kyoto-shiga-ops-monitor.git
   git branch -M main && git push -u origin main
   ```

2. **Settings → Pages → Source** で **「GitHub Actions」** を選択

   公開URL: `https://<ユーザー名>.github.io/kyoto-shiga-ops-monitor/`

   このURLを PC・スマホ・タブレットで開けば、どの端末でも同じ最新データを表示できます。
   Chrome / Safari / Edge いずれでも動作します（外部 CDN に依存せず1ファイルで完結）。

## 設定の変更（スプレッドシート・シート名）

`index.html` の先頭付近にある `CONFIG` を書き換えます。

```js
const CONFIG = {
  sheetId: '1eGcZ2vpvTIjkHVn5Lwnl1MO_W3MwpCmLCOFsjNNfEKY', // 対象スプレッドシート
  sheet: { store:'店舗', chouka:'超過', feedback:'ご意見' },   // シート名
  refreshMinutes: 10
};
```

## 同梱スナップショットを更新したいとき（任意）

通常は不要です（自動で最新を取得するため）。オフライン時の内容を最新化したい場合のみ:

1. スプレッドシートを `sheet.xlsx` としてこのフォルダに保存（`.gitignore` 済み）
2. `python3 -m pip install openpyxl && python3 scripts/extract.py` → `data.json` を再生成
3. `data/data.json` の内容を `index.html` の `const SNAPSHOT = { ... };` に差し替え

## 前提・注意（重要）

- **スプレッドシートの共有設定**：取得はブラウザから匿名で行うため、対象シートが
  **「リンクを知っている全員が閲覧可」** になっている必要があります。
  組織内限定の共有にすると取得に失敗し、同梱スナップショット表示に切り替わります。
- **個人情報**：表示内容には従業員の氏名・従業員番号・店舗別の時間外労働時間・
  お客様のご意見件数が含まれます。リポジトリは **Private** での運用を推奨します。
  無料プランで Public にする場合は、氏名を匿名化した版を別途ご用意ください。
- 画面からスプレッドシートへの**書き込みは行いません**（読み取り専用）。

## 店舗チェック（シート G5 相当の店舗番号入力）

「店舗チェック」シートの入力セル **G5** と同じ考え方で、店舗番号を入力すると
その店舗のデータを表示します。

- 参照する元データは **店舗ﾁｪｯｸd** シート。店舗ごとに **7列ブロック**で構成され、
  ブロック先頭から「種別／カテゴリ／指摘項目／…」、**最終列が指摘回数**です。
  （シートの関数 `filter(店舗ﾁｪｯｸd!<テキスト列>, 店舗ﾁｪｯｸd!<回数列> >= 閾値)` と同じ列を参照）
- 閾値は「店舗チェック」シートの **I4 / J4**（現在は 3回 / 2回）をそのまま読み取ります。
- 表示内容：KPI（店舗・指摘回数合計・最多カテゴリ・全店順位）／カテゴリ別 指摘回数／
  傾向と分析（自動要約）／指摘項目一覧（絞り込み・並び替え）／**全店比較ランキング**。
- 店舗データは最初にタブを開いたときに取得します（16店舗×項目数のため）。
  取得できない場合は同梱スナップショットを表示します。
